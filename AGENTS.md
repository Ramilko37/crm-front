# Agent Instructions

## Перед началом работы

- Каждый раз перед началом работы подтягивать свежие изменения:

```bash
git pull --ff-only
```

- После pull проверить состояние рабочей директории:

```bash
git status --short
```

- Не откатывать, не удалять и не перезаписывать чужие изменения без явного разрешения пользователя.
- Если в рабочем дереве уже есть несвязанные изменения, игнорировать их и работать только в рамках задачи.

## Проект

- Это frontend CRM-приложение.
- Следовать существующей архитектуре, стилю компонентов и паттернам проекта.
- Перед изменениями изучить связанные файлы и существующие аналоги.
- Не добавлять новые библиотеки без необходимости и без проверки, что задачу нельзя решить существующими средствами.
- Не смешивать фичу или багфикс с крупным рефакторингом, если пользователь этого прямо не просил.

## Разработка

- Для поиска по проекту использовать `rg` или `rg --files`.
- Использовать существующие `shared/ui`, `shared/api`, `modules` и локальные helper API.
- Не дублировать API-типы вручную, если есть сгенерированный клиент.
- Не хардкодить URL, токены, пароли и бизнес-константы в компонентах.
- Сохранять изменения минимальными и привязанными к задаче.

## UI/UX

- Соблюдать текущую дизайн-систему проекта.
- Интерфейсы CRM должны быть плотными, спокойными и рабочими, без лендингового оформления.
- Проверять, что интерфейс корректно выглядит на мобильных и десктопных viewport.
- Текст в кнопках, таблицах, карточках и формах не должен ломать layout.
- Для действий использовать понятные controls: кнопки с иконками, меню, tabs, segmented controls, inputs, toggles и checkbox там, где они уместны.

## Проверка

- После изменений по возможности выполнить:

```bash
pnpm lint
pnpm build
```

- Если менялись API-типы или сгенерированный клиент, выполнить:

```bash
pnpm api:pull:cabinet
```

- Если команда не запускается или падает по внешним причинам, явно сообщить пользователю причину.
- Не заявлять, что задача полностью проверена, если проверки не запускались или завершились ошибкой.

## Git

- Не коммитить автоматически без просьбы пользователя.
- В финальном ответе кратко указать измененные файлы и выполненные проверки.
- Не включать в коммит несвязанные изменения пользователя.
